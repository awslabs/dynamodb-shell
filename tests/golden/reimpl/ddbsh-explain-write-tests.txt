# ddbsh-explain-write-tests.txt — golden-parity family for the SEEDED EXPLAIN
# forms: EXPLAIN INSERT, EXPLAIN REPLACE, and EXPLAIN ALTER TABLE ... SET TTL
# (phase 2i, AI-2i-B).
#
# Unlike the pure-serialization EXPLAIN DDL forms (ddbsh-explain-ddl-tests.txt),
# these EXPLAIN forms probe the live table before serializing:
#   * INSERT / REPLACE resolve the table's key schema via DescribeTable to build
#     the PutItem (INSERT adds the attribute_not_exists(#pk) condition; arch §7,
#     §8) — the same reason EXPLAIN SELECT is not backend-free (arch §11).
#   * ALTER ... SET TTL runs a DescribeTTL probe (arch §7, the AlterTtlCmd =
#     DescribeTTL + UpdateTimeToLive); EXPLAIN prints only the resulting
#     UpdateTimeToLive serialization.
# So this family is SEEDED: each test's single -c creates a real table (the
# CREATE waits for ACTIVE), runs the EXPLAIN form(s) against it, then drops it
# (self-contained lifecycle, one create/drop per run). The CREATE/DROP status
# tokens bracket the deterministic EXPLAIN serialization(s).
#
# The expected outputs were RECORDED FROM THE ORIGINAL ddbsh (production
# `ddbsh-old` oracle, driven through the golden harness, D-2i-2) and are
# reproduced byte-for-byte by the reimplementation. EXPLAIN output is
# deterministic (no sort); the table names are fixed so the goldens are stable.
#
# WARNING: this family creates and drops REAL DynamoDB tables
# (ddbsh_iexp_insert, ddbsh_ttl) on each run (us-east-1). It is self-cleaning.

add_test(NAME iexp-insert-replace COMMAND ddbshtest -q -T ${RD_REIMPL}/iexp-insert-replace.exp -c "create table ddbsh_iexp_insert ( pk number ) primary key (pk hash); explain insert into ddbsh_iexp_insert (pk, a) values (1, 2); explain replace into ddbsh_iexp_insert (pk, a) values (1, 2); drop table ddbsh_iexp_insert;")

add_test(NAME iexp-alter-ttl COMMAND ddbshtest -q -T ${RD_REIMPL}/iexp-alter-ttl.exp -c "create table ddbsh_ttl ( pk number ) primary key (pk hash); explain alter table ddbsh_ttl set ttl (expiry); drop table ddbsh_ttl;")
